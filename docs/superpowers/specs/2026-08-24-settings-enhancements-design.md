# 设置增强设计

## 1. 目标与范围

当前 `GET /api/settings/mteam` 只返回是否已配置、统一掩码和更新时间。前端无法取得已保存的站点地址、Header 结构、User-Agent 和请求超时，因此每次进入设置页都会显示硬编码默认值。用户若只修改其中一项并保存，前端还可能用默认值或空值覆盖原配置。

本次在修复 M-Team 站点配置回显的基础上增加三项能力：

1. M-Team 每日自动签到，提供启用开关、执行时间和最近执行结果。
2. 下载默认值按电影、电视剧、音乐和其他四种类型配置不同保存路径。
3. 搜索结果展示 M-Team 返回的海报图片，并在图片不可用时稳定降级。

本次不修改 qBittorrent 连接配置交互、不新增数据库表结构，也不向浏览器返回任何敏感字段明文。新增配置继续保存在现有 `app_config` 中。

本设计是原总设计的增量说明：M-Team 设置接口由“只返回配置状态”调整为“返回公开字段和敏感字段掩码”，并新增自动签到、分类型下载路径与搜索结果海报；未明确修改的安全、认证和下载约束继续沿用原设计。

## 2. 接口设计

`GET /api/settings/mteam` 和 `PUT /api/settings/mteam` 返回同一份 M-Team 设置视图，包含：

- `configured`：是否已保存配置。
- `updated_at`：最近更新时间。
- `base_url`：站点地址；未配置时使用当前默认地址。
- `headers`：保留已保存的 Header 名称，每个值统一替换为固定掩码。
- `cookie`：已配置 Cookie 时返回固定掩码，否则返回空值。
- `user_agent`：已保存的 User-Agent；未配置时使用当前默认值。
- `timeout`：已保存的请求超时；未配置时使用当前默认值。

固定掩码由后端集中定义，前后端不各自维护不同字面量。响应不得包含 Header、Cookie 或其他认证值的明文。

`PUT /api/settings/mteam` 继续接受完整表单。当 Header 某个值或 Cookie 等于固定掩码时，后端从现有加密配置中保留对应原值；输入新值时覆盖原值。删除 Header 键表示删除该 Header，Cookie 提交空值表示删除 Cookie。首次配置时不允许把掩码当作真实凭据保存。

## 3. M-Team 配置回显

设置页加载完成后，M-Team 表单使用接口返回值初始化，而不是继续显示硬编码默认值：

- 站点地址、User-Agent 和请求超时显示已保存值。
- Header JSON 显示原 Header 名称和掩码值。
- Cookie 输入框显示掩码值。
- 用户不修改敏感字段即可调整其他字段并保存，原认证信息保持不变。
- 用户输入新的 Header 值或 Cookie 时，新值正常覆盖原值。

表单只在异步配置加载完成后挂载，避免 `useState` 在初次空状态下锁定默认值。现有状态提示、连接测试与视觉样式保持不变。

## 4. 每日自动签到

设置页在 M-Team 区域增加自动签到开关和每日执行时间。默认关闭，执行时间按应用配置的 `TZ` 解释。设置页展示最近一次签到的执行时间、成功或失败状态及脱敏消息。

应用在 FastAPI 生命周期内启动单个后台调度任务：

1. 读取签到开关、每日执行时间和最近成功日期。
2. 计算下一次执行时间，不使用固定间隔累加，避免重启或夏令时导致时间漂移。
3. 到达执行时间后，使用已保存的 M-Team 认证配置调用签到接口。
4. 持久化本次执行时间、状态和脱敏结果，再计算下一次执行时间。

同一站点按应用时区的自然日最多记录一次成功签到。应用在当天执行时间之后启动时，若当天尚未成功签到，则补执行一次；已成功时不重复请求。首次签到失败后，当天只自动重试一次，重试间隔固定为 30 分钟，避免第三方异常时高频请求。关闭开关后不再创建新的签到请求，正在执行的单次请求允许完成并记录结果。

签到配置和状态使用新的固定配置键保存在 `app_config`，不新增表。站点客户端封装签到调用、超时和响应解析，调度器只负责触发与状态持久化。M-Team 尚未配置时不发起请求，并记录“站点尚未配置”的失败状态。

## 5. 分类型下载路径

下载默认设置保留默认分类和默认启动方式，将单个 `save_path` 扩展为固定路径映射：

- `movie`：电影保存路径。
- `tv`：电视剧保存路径。
- `music`：音乐保存路径。
- `other`：其他类型及未知类型的兜底路径。

四个路径都必须是 Unix 或 Windows 绝对路径。读取旧版只包含 `save_path` 的配置时，将该路径作为四种类型的初始值；保存新版配置后使用路径映射，不修改数据库结构。

搜索结果展开下载参数时，根据结果的规范化 `category` 选择默认保存路径。`movie`、`tv`、`music` 使用对应路径，`all` 或未来未知类型使用 `other`。用户仍可在单次推送前修改保存路径，后端继续校验最终路径为绝对路径。

## 6. 搜索结果海报

M-Team 搜索响应中的 `imageList` 作为海报来源。适配器选取列表中第一个合法 HTTPS URL，规范化为搜索结果的可选 `poster_url`；列表为空、格式错误或只包含非 HTTPS 地址时返回空值。搜索 API 不为海报额外请求 M-Team、TMDB 或豆瓣，避免放大搜索延迟和第三方调用次数。

桌面端继续使用紧凑结果表，在标题列左侧展示固定 `48 × 72` 像素缩略图，标题与描述在右侧排列。展开下载参数时展示 `120 × 180` 像素海报。移动端使用固定 `44 × 66` 像素缩略图，不因图片加载、失败或标题长度改变操作区域位置。

图片使用原生懒加载、异步解码、`object-fit: cover` 和 `referrerPolicy="no-referrer"`。缺少海报、加载失败或 URL 被浏览器拒绝时，在相同尺寸区域显示中性的图片占位图标，避免布局跳动。海报仅作辅助信息，不作为打开详情或执行推送的唯一交互入口，并提供基于资源标题的替代文本。

首版由浏览器直接加载 HTTPS 图片，不新增通用图片代理或本地缓存。这样可以避免后端代理任意站外 URL 导致的 SSRF 风险；后续若需要缓存，必须单独设计域名白名单、响应大小限制、内容类型校验和缓存淘汰策略。

## 7. 安全与错误处理

- 加密配置仍只通过服务层读取，API 不直接接触数据库密文。
- Header 值和 Cookie 在响应、日志及测试失败信息中均不得出现明文。
- 掩码保留逻辑在服务层完成，路由只负责请求校验与响应输出。
- 若已保存配置缺少旧版本中的可选字段，返回安全默认值，兼容现有数据。
- JSON 格式错误和现有 URL、超时校验行为保持不变。
- 签到响应和状态消息不得包含 Cookie、Header、完整请求地址或第三方原始响应体。
- 后台签到失败不得导致应用退出；错误只更新签到状态并按规则安排后续尝试。
- 调度任务随应用生命周期停止，关闭时不遗留独立进程。
- 海报 URL 只接受 HTTPS，不把任意图片地址转发给后端请求。

## 8. 测试与验收

后端先增加失败测试，覆盖：

1. 保存后能读回站点地址、User-Agent、超时和 Header 名称。
2. Header 值与 Cookie 只以掩码返回，响应中不存在明文凭据。
3. 提交掩码并修改公开字段后，原 Header 与 Cookie 仍可用于连接配置。
4. 输入新凭据时覆盖旧值，删除字段时按约定移除。

前端先增加失败测试，覆盖设置接口返回已保存配置后，表单正确显示公开字段和敏感字段掩码，并在未修改敏感字段时提交保留语义所需的载荷。

自动签到测试覆盖：开关关闭不执行、到点执行、启动后补签、同日成功不重复、失败状态脱敏、缺少站点配置和应用关闭时任务停止。测试使用可控时钟和模拟 M-Team 边界，不等待真实时间，也不访问真实站点。

分类型路径测试覆盖：四类路径的保存与读取、绝对路径校验、旧版单路径配置迁移读取、电影/电视剧/音乐匹配和未知类型回退到 `other`。前端覆盖设置表单保存以及搜索结果按类型预填路径。

海报测试覆盖：从 `imageList` 选择首个 HTTPS URL、忽略空值和非 HTTPS URL、API 输出可选 `poster_url`、前端正常图片渲染、缺失图片占位和加载失败占位。前端测试同时确认图片有替代文本并启用懒加载。

验收时运行后端设置与调度测试、完整后端测试、前端测试、TypeScript 检查和生产构建；再在浏览器中执行以下交互检查：

1. 打开设置页，确认 M-Team 已保存配置正确回显且敏感值保持掩码。
2. 开启每日签到、选择执行时间并保存，刷新后确认设置和最近状态可回显。
3. 配置四种下载路径，分别展开不同类型搜索结果，确认默认路径匹配且可单次覆盖。
4. 搜索带海报和不带海报的资源，确认缩略图、展开海报和失败占位均不引发布局跳动。
5. 确认页面无相关控制台错误，敏感信息未出现在网络响应明文中。
